# 표정 분석 (fromis_9 팬 콘텐츠용)

영상을 보는 동안 내 표정을 실시간으로 분석해서 감정 수치를 화면에 띄우는 웹페이지.
화면 녹화해서 숏폼 소재로 쓰는 것이 목적이라 "녹화했을 때 그림"에 맞춰 만들었다.

- 감정 판정은 **face-api.js 표정 모델** 결과다. 화면의 값을 더하면 항상 100%가 된다.
- 표시하는 감정은 **무표정 · 행복 · 슬픔 · 분노 · 놀람 5종.** 모델은 두려움·혐오까지 7종을 계산하지만,
  이 둘은 다른 감정과 잘 구분되지 않고(학습 표본도 가장 적다) 오히려 화면을 어지럽혀서 뺐다.
  뺀 몫은 버리지 않고 남은 5종에 다시 나눠 준다. 되살리려면 `js/config.js`의 `HIDDEN_KEYS`를 비우면 된다.
- 라벨 이름만 한국어로 옮겼고, `L` 키를 누르면 영어 원본 라벨로 바뀐다.
- 모든 처리는 브라우저 안에서만 이루어진다. 영상도 웹캠 화면도 어디로도 전송·저장되지 않는다.

---

## 실행 방법

카메라는 `https` 또는 `localhost`에서만 켜진다. **파일을 더블클릭해서 열면 동작하지 않는다.**

```bash
python -m http.server 5690 --directory "C:\Users\samsung\Desktop\fromis9-emotion" --bind 127.0.0.1
```

그리고 브라우저에서 http://127.0.0.1:5690 접속. (크롬 권장)

영상은 화면 가운데 **"눌러서 영상 열기"** 를 누르면 뜨는 팝업에서 넣는다. 유튜브 주소를 붙여넣거나
영상 파일을 고르면 되고, 영상 칸에 파일을 그냥 끌어다 놓아도 열린다. 상단 바의 [영상 열기] 버튼이나 `O` 키도 같은 팝업이다.

## 화면 구성

```
┌───────────────────────────┬────────┐
│                           │  웹캠   │
│        영상 (16:9)         │        │
│                           │ ┌────┐ │
│                           │ │수치│ │
└───────────────────────────┴─┴────┴─┘
      16 : 9                  9 : 16      ← 무대 전체는 약 2.34 : 1
```

무대 비율은 **고정하지 않고 내용에서 거꾸로 계산한다.** 영상 칸을 16:9로, 웹캠 칸을 9:16으로 두고
둘 다 높이를 꽉 채우므로 **무대 안에 남는 검은 여백이 없다.** (16:9로 고정하면 영상 칸이 세로로 길어져서
영상 위아래에만 검은 띠가 생기고 좌우가 비대칭으로 보인다.)

웹캠 칸이 그대로 9:16이라 **숏폼용으로는 웹캠 칸만 잘라내면 바로 맞는다.**

### 세로 모드 (`V` 키)

숏폼 프레임 그대로 찍고 싶을 때 쓴다. 무대가 9:16이 되고 위에서부터 영상 / 웹캠 / 수치로 쌓인다.

```
┌────────────┐
│  영상 16:9  │  31.6%
├────────────┤
│  웹캠 16:9  │  31.6%
├────────────┤
│            │
│    수치     │  36.8%
│            │
└────────────┘
```

**9:16 화면에서 16:9 영상을 가로로 꽉 채우면 높이의 31.6%가 된다. 이건 바꿀 수 없다.**
더 키우려면 영상 좌우를 잘라야 하는데 그러면 유튜브 광고 스킵 버튼(우하단)이 잘려서 못 누른다.
그래서 영상을 키우는 대신 **웹캠도 16:9로 맞춰 영상과 정확히 1:1**이 되게 했다.
웹캠은 원래 16:9로 들어오므로 잘리는 부분도 없다. 남는 아래 공간은 전부 수치 패널이 쓴다.
(1080 높이 기준 패널 기본 글자가 가로 모드 20px → 세로 모드 27px로 커진다.)

세로 모드에서는 수치 패널이 항상 아래로 분리된다. 웹캠 띠가 얇아서 겹치면 얼굴을 가리기 때문이다.

감정 수치는 **웹캠 위에 겹쳐서** 나온다(밈 원본 형태). `P` 키를 누르면 웹캠 아래로 분리된다.
크기는 설정의 **수치 크기**(작게/보통/크게/아주 크게, 기본 크게)로 조절한다. 웹캠 칸 너비에 비례하므로
창 크기를 바꿔도 비율이 유지된다.

영상 칸 위에는 아무것도 덮지 않는다. 유튜브 광고 스킵 버튼을 눌러야 하기 때문이다.

## 단축키

| 키 | 기능 |
|---|---|
| `O` | 영상 열기 팝업 |
| `R` | 녹화 모드 (상단 바·설정 전부 숨김) |
| `V` | 가로 16:9 ↔ 세로 9:16 |
| `P` | 수치 패널 겹치기 ↔ 아래 분리 (가로 모드에서만) |
| `L` | 라벨 한국어 ↔ 영어 |
| `Space` | 영상 재생 / 일시정지 |
| `↑` `↓` | 볼륨 |
| `Esc` | 팝업·설정 닫기 · 녹화 모드 해제 |

> **주의:** 유튜브 화면을 한 번 클릭하면 그 뒤로는 키 입력을 유튜브가 가져가서 단축키가 안 먹는다.
> 화면의 다른 곳(웹캠이나 배경)을 한 번 클릭하면 다시 동작한다.

## 수치가 움직이는 방식 (설정에서 조절)

### 반응 속도
추론은 계속 초당 10번 돌지만, **화면에 뜨는 숫자는 지수이동평균으로 천천히 따라간다.** 순간적으로 튄 판정이 무시되고 값이 진득하게 움직인다.

| 설정 | 시간 상수 | 표정을 바꿨을 때 |
|---|---|---|
| 즉각 | 없음 | 모델 출력이 그대로, 초당 10번 갱신 (많이 산만함) |
| 보통 | 0.6초 | 약 1.8초면 새 표정으로 다 넘어감 |
| **느리게 (기본)** | 1.3초 | 1.3초에 63%, 약 3.9초면 다 넘어감 |
| 아주 느리게 | 2.6초 | 훨씬 느긋하게. 정지화면 같은 느낌 |

최고값 강조(앰버)는 **3%p 이상 앞서야** 자리를 넘겨준다. 두 감정이 붙어 있을 때 색이 깜빡이지 않게 하기 위함이다.

### 감정 보정
face-api의 표정 모델은 실사용에서 **neutral과 sad로 심하게 쏠린다.** 웃어도 happy가 잘 안 올라가고 angry·disgusted는 거의 안 뜬다. 그래서 표시 단계에서 두 가지를 적용한다.

1. **온도 스케일링** `p^(1/T)` — 한 감정이 99%를 독식하는 것을 완화
2. **클래스 가중치** — 잘 안 나오는 감정에 이득을 주고 쏠리는 감정은 누른다
   `happy 4.2 · surprised 2.0 · angry 1.7 · sad 0.34 · neutral 0.24`

잡음까지 같이 커지지 않게 바닥값을 잘라내고, 마지막에 합이 100%가 되도록 정규화한다. 실제로 어떻게 바뀌는지:

| 상황 (모델 원본) | 보정 약 | 보정 중(기본) | 보정 강 |
|---|---|---|---|
| 무표정 96 / 슬픔 3 | 무표정 93 | **무표정 79** / 슬픔 12 / 행복 10 | 무표정 71 / 행복 15 |
| 무표정 55 / 행복 35 | 행복 76 | **행복 90** / 무표정 7 | 행복 95 |
| 행복 75 / 무표정 20 | 행복 92 | **행복 97** | 행복 98 |
| 무표정 50 / 슬픔 35 / 분노 12 | 분노 36 | **분노 58** / 슬픔 23 | 분노 70 |
| 놀람 70 / 무표정 20 | 놀람 90 | **놀람 95** / 무표정 5 | 놀람 97 |
| 슬픔 85 / 무표정 10 / 행복 4 | 슬픔 64 / 행복 25 | **행복 59** / 슬픔 34 | 행복 76 |

> **보정을 켜면 화면의 숫자는 모델 원본값이 아니다.** 맨 아랫줄처럼 **1등이 뒤집히기도 한다** —
> 모델이 슬픔 85%로 본 얼굴이 보정 후에는 행복 59%로 나온다. 행복 가중치를 4.2배까지 올린 대가다.
> 순위를 원본에 가깝게 유지하고 싶으면 **보정 → 약**, 완전한 원본은 **보정 → 끔**.
> 지금 어떤 상태인지는 상태줄 맨 끝에 항상 표시된다.

## 이 수치가 정확한가

솔직하게: **아니다.** 재미로 쓰는 물건이라고 보는 게 맞다. 이유를 순서대로 적는다.

**모델이 실제로 하는 일** — 얼굴을 잘라내 **112×112 컬러**로 줄이고, 작은 CNN이 특징 256개를 뽑아
7개 숫자를 만든 뒤 **softmax**로 합이 1이 되게 나눈다. 그래서 항상 합계가 100%가 된다.

1. **퍼센트는 확률이 아니다.** softmax 출력일 뿐이고, 신경망의 softmax는 과신하는 것으로 잘 알려져 있다.
   "행복 99%"는 "99% 확신"이라는 뜻이 아니라 그냥 7개 중 이 칸의 점수가 압도적이라는 뜻이다.
2. **'표정 = 감정'이라는 전제부터 논쟁 중이다.** 얼굴 움직임이 내면의 감정과 일대일로 대응하지 않는다는 것이
   심리학계의 대규모 리뷰 결론이다(Barrett 외, 2019). 이 모델이 판정하는 건 "이 얼굴 배치에 사람들이 붙일 라벨"이지
   당신이 무엇을 느끼는지가 아니다.
3. **7종 분류 자체가 어려운 문제다.** 이 계열의 표준 벤치마크(FER-2013)에서 **사람의 정확도가 약 65%**,
   잘 만든 모델이 70% 남짓이다. face-api의 표정 모델은 322KB짜리 속도 위주 모델이고 공식 정확도는 공개돼 있지 않다.
4. **감정별로 학습량이 다르다.** 공개 데이터셋들은 혐오·두려움 표본이 행복·무표정의 1/10 수준인 경우가 많다.
   이 둘이 유독 안 뜨거나 엉뚱한 순간에 튀는 건 학습 단계에서 이미 불리했기 때문이고, 그래서 화면에서 아예 뺐다.
5. **정면·과장된 사진으로 배웠다.** 웹캠 각도, 조명, 안경, 마스크, 머리카락이 얼굴을 가리면 판정이 흔들리고
   보통 무표정·슬픔 쪽으로 쏠린다.

**그럼 위의 보정은 정확도를 올린 건가** — 아니다. 온도 스케일링과 클래스 가중치는 실제로 쓰이는 정식 기법이지만,
원래는 정답이 붙은 검증 데이터로 수치를 맞춰야 한다. 여기 값들은 **"이렇게 보이면 좋겠다"는 피드백을 보고 손으로 맞춘 것**이다.
그러니 보정은 정확도를 개선한 게 아니라 **보기 좋게 만든 것**이고, 그래서 언제든 끌 수 있게 해뒀다.

**그래도 믿을 만한 것** — ① 얼굴을 찾는 것 자체 ② **변화의 방향**(웃으면 행복이 오르고 눈썹을 찌푸리면 분노가 오른다)
③ 같은 사람·같은 조명에서의 시간적 일관성. 숏폼 소재로 쓰는 데는 이 정도면 충분하다.

**믿으면 안 되는 것** — 절대 퍼센트 값, 사람끼리 비교, 그리고 "이 사람이 지금 슬프다" 같은 결론.

## 녹화 팁

- 무대 바깥은 순수 검정이다. OBS 창 캡처 후 무대 영역만 잘라내면 된다. `R` 키(녹화 모드)로 상단 바를 숨기면 무대가 창을 가로로 꽉 채운다. F11 전체화면까지 쓰면 픽셀을 가장 많이 쓴다.
- 1920×1080 창 기준 무대는 1920×820, 그 안에서 영상 1458×820 + 웹캠 461×820.
- **숏폼(9:16)은 두 가지 방법이 있다.**
  ① `V` 키로 **세로 모드**를 켜고 무대(9:16)를 그대로 잘라낸다 — 영상·웹캠·수치가 한 화면에 들어간다.
  1080 높이 창에서 무대가 608×1080이므로, 최대 선명도가 필요하면 F11 전체화면으로 키운 뒤 녹화한다.
  ② 가로로 녹화한 뒤 편집에서 **웹캠 칸만** 잘라낸다 — 웹캠 칸이 정확히 9:16이라 그대로 맞고 해상도도 더 높다. 대신 영상은 안 들어간다.
- 설정의 **웹캠 폭**으로 얼굴 크기를 조절한다. 얼굴이 잘리면 **웹캠 맞춤 → 전체 보기**로 바꾼다.

## 성능

- 기본 추론 주기는 **10Hz**. 표정 자체가 0.2~0.5초 단위로 변해서 그 이상은 GPU만 먹고 얻는 게 없다.
- 추론 시간이 주기의 60%를 넘으면 스스로 주기를 늘린다. 상태줄의 `hz` 값이 실제 동작 주기다.
- 버벅이면 설정에서 **저사양(5hz · 160px)** 을 누른다.
- 상태줄 `ms`는 한 번 추론에 걸리는 실제 시간, 그 뒤는 tfjs 백엔드(`webgl` 정상 / `cpu`면 느림), 맨 끝은 보정 상태.

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| `camera blocked` | 주소창 왼쪽 자물쇠 → 카메라 → 허용 → 새로고침 |
| `camera busy` | Zoom·OBS 가상카메라 등이 카메라를 잡고 있다. 끄고 새로고침 |
| `embed blocked` | 임베드가 막혔거나 없는 영상. **영상 열기 → 파일**로 받아둔 영상을 쓴다 |
| `referrer blocked` (153) | `file://` 로 열었거나 광고차단 확장 때문. localhost 주소로 열 것 |
| `api blocked` | 광고차단 확장이 유튜브 스크립트를 막았다. 확장을 끄거나 파일 재생 사용 |
| `model load failed` | `models` 폴더가 같이 올라갔는지 확인 |
| 얼굴 인식이 잘 안 됨 | 얼굴에 빛이 오게 하고, 카메라에 조금 더 가까이. 설정에서 감지 입력을 320으로 |
| 특정 감정이 안 뜸 | 설정에서 **감정 보정 → 강** |

주소 뒤에 `?debug=1` 을 붙이면 콘솔에서 `__f9` 로 내부 객체(detector·panel·overlay·smoother)에 접근할 수 있다.


몇 분 뒤 `https://<계정>.github.io/<저장소>/` 로 접속하면 된다. https라서 카메라도 정상 동작한다.
